# 怪物视角移植与科技评估

## 范围与兼容

以 VMDieCore `7f74197` 为基线，整合本地怪物视角 1.0.2，核心版本提升到 0.2.0。五族身体、模型、第一人称、种族选择与网络同步、搜打撤风格大字号 UI、种族科技基础实现，以及无用之物燃烧兼容补丁纳入同一个核心 JAR。血族继续使用玩家自身模型和皮肤。**种族科技整体尚未完成，当前配方种族限制可被其他模组绕过。**

主入口由 `VMDieCore` 调用 `MonsterPerspective.initialize`；客户端入口归属 `vmdiecore`。代码包改为 `org.dishanhai.vmdiecore.monster`，不再声明第二个独立模组。

保留以下已发布数据，避免升级丢失：

- `monsterperspective:*` 物品、配方、材料、纹理、属性修饰符和网络包 ID。
- 玩家 `mp_*` 持久数据及傀儡复活冷却；种族死亡继承与原有冷却规则。
- `monsterperspective-server.toml` 文件名和配置项，可继续使用已有存档及 `defaultconfigs` 中的设置。
- 牛奶产骨条件：骷髅或血族在开始喝牛奶时满血。创造飞行、模组提供的飞行权限不受下沉影响。

配置文件的“提供者目录”和注册 ID 分开处理：Modular Golems 的材料配置、Curios 的玩家槽位配置移动到 `data/vmdiecore/`，配置内容仍引用原来的 `monsterperspective:*`。傀儡模组只枚举已加载模组的配置目录；直接复制旧目录会造成材料缺失，甚至在傀儡死亡掉落时越界。资源生成脚本也同步修改了这两个入口。

## 种族科技：未完成

目前完成了四族科技基础物品、配方、效果及核心注册、资源加载、依赖和脚本接口的移植。种族科技的完整解锁限制仍未完成，不能据此宣称整个科技体系已实现。

**已知问题：配方种族检查只挂在原版合成菜单流程。其他模组可以通过自己的合成、自动化或机器流程绕过该检查，取得本应受种族限制的科技产物。** 原版合成路径的回归通过，不代表跨模组限制成立。

| 科技 | 处理 | 依据与边界 |
| --- | --- | --- |
| 僵尸克隆 | 基础实现已移植；配方权限未完成 | 肉部件、原生装配和消耗替身复活使用 Modular Golems；保持已有肉傀儡材料 ID。 |
| 骷髅灵魂 | 基础实现已移植；配方权限未完成 | 捕魂、骨部件、复活冷却、满血牛奶产骨和 Curios 护符加速保留；检验真实饰品回调和卸下清理。 |
| 末影传送 | 基础实现已移植；配方权限未完成 | 卷轴、绑定/交换、目标失联破碎、无限珍珠与割取珍珠逻辑保留。Ender IO 未安装，条件配方未实测。 |
| 节肢纺织 | 基础实现已移植；配方权限未完成 | 八种蛛丝布、附魔适用性与冲突检查、毒液合成/酿造替代保留。 |
| 血族共享 | 已移植共享判定；完整科技权限待补 | 共享四系科技，不继承其他种族的身体弱点。 |

AnvilCraft、LDLib2、MBD2 是核心原有必需前置。本次保留已有基础配方，尚未为种族科技建立覆盖整合包各合成入口的权限方案。后续需要结合实际模组的合成方式决定配方和联动的重构范围，不能以“代码已移植”作为“科技已完成”的结论。

现有检查覆盖原版背包合成、原版工作台及其批量合成，以及在这些原版菜单内进行的傀儡部件转换；它不构成所有模组合成入口的统一权限。机器自动化没有统一的“正在操作的玩家”，需要先明确按机器拥有者、领地或操作者解锁，再补齐对应流程的限制。

后续待完成：

- 梳理整合包实际提供的工作台、自动合成和机器流程，记录可绕过的入口。
- 明确跨模组的科技权限规则，实施服务器端限制；仅隐藏配方或提供查询接口不足以完成限制。
- 增加无科技种族、授权种族、血族、切换种族和自动化流程的回归，确认绕过问题得到解决。

## KubeJS 接口

新增服务端只读绑定 `VMDieTechnology`，不需要脚本访问或修改内部 NBT：

```js
// kubejs/server_scripts/ 中、具有 player 的服务器事件内使用。
const race = String(VMDieTechnology.getRace(player)) // 未选种族返回空字符串
const unlocked = VMDieTechnology.hasTech(player, 'enderman')
```

`hasTech` 接受 `zombie`、`skeleton`、`enderman`、`arthropod`，血族对四者均返回 true，未选种族均返回 false。未知科技 ID 会报错，避免拼写错误悄悄放行。**接口仅提供查询，不会自动限制其他模组的配方；跨模组权限尚未实现。** 具体事件的取消或机器逻辑仍由调用方处理。原 `VMDieStacking` 启动脚本绑定保留。

## 构建与验证方式

Java 21 / NeoForge 21.1.266。依赖默认通过公开 Maven 下载固定版本，也可在整合包内使用已安装 JAR：

```powershell
.\gradlew.bat build '-PpackModsDir=../mods'
.\gradlew.bat runGameTestServer '-PpackModsDir=../mods'
```

与无用之物及 KubeJS 联测时，用 `-PintegrationModsDir=<目录>` 指定额外的开发依赖。该目录只放额外联测模组及前置，不应重复放核心必需前置、Curios、Modular Golems 和 L2Library。测试用脚本由 `tools/integration/kubejs/` 自动复制到隔离的测试目录，验证原堆叠绑定及新科技绑定。KubeJS 未安装时不要求脚本验证标志。

所有 GameTest 源码和空白结构放在 `src/gameTest/`，参与开发运行，不打入正式 JAR。正式 JAR 仍携带 MIT 代码声明和 Modular Golems 派生纹理归属。Curios 与 Modular Golems 保持可选依赖，不嵌入第三方 JAR；已有相关科技联动需要安装它们，安装前置不会补齐上述跨模组权限限制。

输出：`build/libs/vmdiecore-0.2.0.jar` 和 `vmdiecore-0.2.0-sources.jar`。新核心与旧独立怪物视角不能并装，元数据已提供明确的冲突提示。原核心首次登录传送至 `vmdiecore:origin` 的行为仍然存在；这与种族数据兼容是两个独立行为。

具体执行结果和验证范围见 [移植验证记录](移植验证记录.md)。
